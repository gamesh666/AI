# AIVMS 平台說明與串接訴求

> 對象：REACH AI Office Vision System 開發團隊
> 目的：說明我方平台是什麼、為什麼要串接、雙方各自負責什麼
> 技術細節請見另一份文件：`02-REACH-需新增功能規格.md`

---

## 1. 我們是什麼

**AIVMS（AI 智慧影像監控與邊緣運算管理平台）** 是一個**多場域、多 Edge 的中央管理與顯示平台**。

- 平台本身**不做任何 AI 辨識**，不拉攝影機、不跑 YOLO。
- 每台 Edge（例如 REACH）**獨立作業、獨立辨識**，平台只負責**接收與顯示**：
  - 各 Edge 的**即時辨識畫面**（Edge 已畫好框的影像）
  - 各 Edge 回報的**辨識結果 / 事件紀錄（LOG）**，內容由 Edge 自己決定
  - 各 Edge 與攝影機的**在線狀態與健康資訊**
- 平台不解讀事件內容：Edge 之後新增或修改辨識項目，**平台不需要改程式**。

```text
  ┌──────────── REACH（Edge，現場）────────────┐            ┌────────── AIVMS 平台（中央）──────────┐
  │ 攝影機 RTSP → YOLO → ROI / 離席狀態機        │            │                                       │
  │        │                │                    │  H.264     │  MediaMTX ──► 瀏覽器即時畫面（WebRTC/HLS） │
  │        └─ 已畫框畫面 ───┼───────────────────┼──RTSP────►│                                       │
  │                         └─ 事件 / 狀態 ──────┼──MQTT────►│  後端 ──► PostgreSQL ──► 紀錄頁 / 總覽    │
  │ REACH 自己的網頁、DB、日報（照舊）           │  JSON      │                                       │
  └──────────────────────────────────────────────┘            └───────────────────────────────────────┘
```

## 2. 平台提供的功能

| 功能 | 說明 |
|------|------|
| 多場域、多 Edge 管理 | 場域、邊緣裝置、攝影機集中管理；裝置在線 / 離線即時顯示 |
| 即時監看 | 1×1 / 2×2 / 3×3 / 4×4 宮格，播放各 Edge 推上來的 AI 標註畫面 |
| Edge 紀錄 | 所有 Edge 回報的事件，可依時間、場域、裝置、攝影機、類型、等級篩選與搜尋，即時更新 |
| 快照 | 事件可附快照，平台會把 Edge 提供的框畫在快照上 |
| 權限 | 帳號登入、admin / operator / viewer 角色 |
| 介面語言 | 繁體中文 / 简体中文 / English |

## 3. 為什麼要串接

- 讓管理者在**一個畫面**看到所有場域（BIMer 辦公室與其他場域）的即時影像與事件。
- REACH 繼續專注在辦公室離席判斷，不需要自己做多場域管理。
- 之後若有其他 Edge（工地、安全帽、入侵偵測…），都用同一套方式接進來。

## 4. 雙方分工

| 項目 | REACH 負責 | AIVMS 平台負責 |
|------|------------|----------------|
| 攝影機連線、RTSP 帳密 | ✅（帳密留在 REACH，不交給平台） | — |
| YOLO、ROI、離席狀態機、工作時段 | ✅ | — |
| 員工、工位、Assignment、日報 | ✅（照 REACH 規格，**不需要搬到平台**） | — |
| 把已畫框的畫面推到平台 | ✅ 新增 | 接收、播放 |
| 把事件 / 狀態送到平台 | ✅ 新增 | 保存、顯示、篩選、即時推播 |
| 帳號權限、多場域總覽 | — | ✅ |

**REACH 原有功能完全不變**：自己的網頁、MJPEG、PostgreSQL、日報、ROI 編輯器照舊運作。
這次只需要**額外新增一個「對外回報」模組**，失效時也不能影響 REACH 本身。

## 5. 我們的訴求（摘要）

請 REACH 新增一個模組（建議 `app/integrations/aivms_bridge.py`），做到：

1. **登記攝影機**：啟動時告訴平台有哪兩支攝影機。
2. **即時辨識畫面**：把 REACH 現在畫好框的畫面，額外編成 H.264 推到平台。
3. **事件回報**：正式離席事件（成立、回座、自動結束、取消）送到平台；同一事件用同一個 ID 更新。
4. **狀態回報**：每 10 秒心跳、每 5 秒攝影機狀態。
5. **可開關、不影響本體**：設定關閉或平台斷線時，REACH 一切照常。

詳細格式、欄位、驗收方式見 `02-REACH-需新增功能規格.md`。

## 6. 平台會提供給 REACH 的資訊

以下資訊**由平台管理員另外以安全管道提供**（不寫在文件、不放 Git）：

| 項目 | 範例 / 說明 |
|------|-------------|
| 平台 API 位址 | `http://<平台IP>:8000/api/v1` |
| 裝置 ID | `REACH01`（平台上建立） |
| 裝置 API 金鑰 | 平台建立裝置時產生，只顯示一次 |
| MQTT 位址 / 帳號 / 密碼 | `<平台IP>:1883` |
| 影像推流位址 | `rtsp://<平台IP>:8554`（跨網際網路可用 SRT `<平台IP>:8890/udp`） |

網路需求：REACH 主機需能**主動連出**到平台的 `8000/tcp`、`1883/tcp`、`8554/tcp`（或 `8890/udp`），
上傳快照另需 `9000/tcp`。
平台**不會**主動連進 REACH，也不需要 REACH 開任何對外 port。

## 7. 資安與隱私原則

- 攝影機位址與帳密**只留在 REACH**，平台不需要、也不會保存。
- 裝置金鑰、MQTT 密碼請放在 REACH 的 env 檔（例如 `/etc/reach-ai-office-vision/office-vision.env`），
  **不得**寫進程式、Git、log 或前端。
- 事件中的個人資料以**最少必要**為原則：建議只送 `employee_id`；是否送員工姓名由雙方另行確認。
- 影像只走 H.264 串流，**不**透過 MQTT / Base64 / WebSocket 傳送。

## 9. 聯絡與測試

雙方約定一個測試時段：平台端建立 `REACH01` 並提供連線資訊 → REACH 端啟用模組 →
雙方一起依 `02` 文件第 9 節的驗收清單逐項確認。
